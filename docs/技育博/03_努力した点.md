# 努力した点・こだわり

## 1. AI 出力の不安定さと正面から向き合った

LLM（Gemini）は同じプロンプトでも出力形式が変わることがある。  
「JSON を返して」と指示しても Markdown コードブロック（` ```json ` ）で包まれて返ってきたり、文字列内のダブルクォートが二重になってパースエラーになるケースが実運用で頻発した。

**対処**: 正規表現とフォールバック処理の多段構成で自己修復パーサーを実装。  
Markdown ブロックの剥ぎ取り → JSON.parse → 失敗時にダブルクォート修復 → 再試行 → それでも失敗なら 100 件超の事前定義ミッションから選択、という多層フォールバックにより、**AI が壊れてもユーザー体験が途切れない**設計にした。

---

## 2. 「圏外でも使える」を本気で実装した

散歩中は通信が不安定になりやすい。「記録しようとしたら保存できなかった」という体験を避けるために、オフライン対応に時間をかけた。

- **Service Worker** でアルバムページをキャッシュし、圏外でも過去の記録を閲覧できる
- **localStorage** に保存失敗ログをキューとして積み、Service Worker の Background Sync でオンライン復帰後に自動送信する
- PWA として「ホーム画面追加」に対応し、ネイティブアプリ感覚のオフライン体験を実現

単に Service Worker を設定するだけでなく、「ローカルが一次記録、Firestore が Source of Truth」というデータフローを明確に設計することに苦労した。

---

## 3. プロンプトエンジニアリングで「使えるミッション」を生み出す

単純に「散歩のお題を作って」とだけ指示すると、ありきたりな内容しか返ってこない。  
以下の工夫でミッションの質を高めた。

- **コンテキスト注入**: 現在地・時刻・明るさ（6段階）を渡すことで状況に即したミッションを生成
- **バリエーション制御**: 約 30% の確率で「時間制約付きお題」を生成するよう確率的に指示し、単調さを防ぐ
- **安全ガードレール**: 「危険行為・私有地侵入・他者のプライバシー侵害を促す内容は生成しない」をシステムプロンプトに明記し、Gemini の HarmCategory フィルタと二重で安全策を設けた
- **文字数制限**: モバイル画面で読みやすいよう 50 字以内を厳守させる

プロンプトの試行錯誤を重ね、「朝の住宅地」「夜の繁華街」「昼の公園」など場面ごとに自然なミッションが出るまで調整した。

## 4. 認証の設計：メールなしでセキュリティを担保する

メールアドレスを使わない独自認証は、体験の摩擦を下げる一方でセキュリティリスクを生む。  
その両立のために以下の工夫をした。

- パスワードは **bcrypt（salt=10）** でサーバーサイドにのみ保存。クライアントにハッシュを渡さない
- ログイン試行に **IP + ユーザーID のレート制限**（5回/15分）をかけ、ブルートフォース攻撃を抑制
- Firebase Anonymous Auth とアプリ独自認証を組み合わせた2層構造で、セッション管理と認証情報を分離
- 予約語チェック（`admin`, `system` 等の前方一致禁止）でID空間の衝突・なりすましリスクを軽減

---

## 5. 画像まわりのモバイル最適化

スマートフォンのカメラは解像度が高く、無圧縮で Cloudinary にアップロードするとメモリ不足やタイムアウトが起きやすい。

- Canvas API でクライアント側に **1024×1024・品質 80%** に事前圧縮
- 圧縮後も容量が超過する場合は品質を段階的に下げて再圧縮（動的品質調整）
- アップロード完了後は Base64 データを即座に破棄し、メモリを解放
- EXIF から撮影時刻を取得し、「ミッション実行中に撮ったかどうか」をフラグ記録

古い Android 端末でも快適に動作するよう、何度もデバイステストを繰り返した。

## 6. 管理機能を本番運用を想定して作り込んだ

個人開発では「とりあえず動くもの」で済ませがちな管理機能を、実際の運用を想定して設計した。

- **お問い合わせ管理**: ステータス（新規 → 確認済 → 対応中 → 解決済 → クローズ）のワークフロー、担当者アサイン、内部メモ機能
- **監査ログ**: 管理者が行ったすべての操作を Firestore に記録し、後から追跡できる
- **メンテナンスモード**: スーパー管理者がワンクリックでサービスを停止・再開できる機能フラグ
- **ロール分離**: superadmin / admin / moderator で権限を細かく制御し、誤操作リスクを低減
- **JWT の自動タイムアウト**: 8時間の有効期限 + 30分非アクティブでセッション切れ

「管理者が複数になっても困らない設計」を最初から意識して実装した。

---

## 7. GDPR・プライバシーへの配慮

- アカウント削除時に Firestore のログ全件 + Cloudinary の画像 + localStorage を3段階で完全削除
- バックアップは自分のデータを JSON でエクスポートできる形式とし、ユーザー自身がデータを手元に持てる設計
- 位置情報はプロンプト生成に使うのみで、Firestore には市区町村レベルのテキストのみを保存（座標は保存しない）
