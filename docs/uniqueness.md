# みちくさメモリー（michikusa_memory）の独自性・強み

調査日: 2026-09-18
対象: 本リポジトリ（Next.js 15 / React 19 / Firebase / Cloudinary / Gemini API）

## 1. コンセプトの独自性

「散歩」という受動的・目的のない行為に、**AIが都度生成するミッション（お題）**を与えることでゲーム的な目的性を付与している点が中核的な差別化要素。既存の万歩計・ウォーキングアプリの多くは「歩数・距離・カロリー」という定量指標に軸足を置くが、本アプリは以下の質的な軸を採用している。

- 定量（歩数・距離）ではなく **体験の質**（何を見つけたか、何を感じたか）を記録の中心に据えている
- 記録物は「冒険の書（アルバム）」という物語的なメタファーで蓄積され、日記・スクラップブック的な楽しみを提供する
- ゴールがない散歩に「今日だけのお題」という小さな目的を与えることで、行動のハードルを下げている

## 2. コンテキスト適応型のミッション生成

`app/api/ai/mission/route.ts` と `lib/geolocation.ts` の組み合わせが特徴的。

- 位置情報（国・地域）、現地時刻、**明るさレベル**（`dark/early_morning/morning/afternoon/evening/night` の6段階）をGemini APIのプロンプトに渡し、状況に即したミッションを生成する
- Nominatim（OSM）による無料リバースジオコーディングと、ブラウザ標準の`Intl.DateTimeFormat`によるタイムゾーン取得を組み合わせ、**外部有料APIに依存せず**位置・時間コンテキストを構築している
- プロンプト内で「約30%の確率で時間制約付きのお題を出す」という確率的なバリエーション制御を明示し、単調な繰り返しを避ける設計になっている（`app/api/ai/mission/route.ts:67`)
- 安全性ガードレール（危険行為・私有地侵入・プライバシー侵害の回避）をシステムプロンプトに明記し、Gemini側のHarmCategoryセーフティ設定も併用する二重の安全対策

## 3. オフラインファースト・フォールバック設計

AI生成が失敗してもユーザー体験が途切れない設計になっている点は、外部AI APIに依存するアプリとして質が高い。

- `data/fallbackMissions.ts` / `data/missions.json` に事前定義ミッションを持ち、Gemini APIキー未設定・レスポンス不正・JSON パース失敗など、あらゆる失敗経路で自動フォールバックする（`getRandomFallback()`)
- AIのレスポンスがMarkdownコードブロックで返る、ダブルクォートが二重になる、といった実運用で頻発するLLM出力の揺れに対する**自己修復的パース処理**を実装済み（`route.ts:190-220`）
- PWA + Service Worker + `localStorage`同期キュー（`lib/syncManager.ts`）により、オフラインで記録したログをオンライン復帰時に自動でFirestoreに同期する「ローカルファースト、FirestoreがSource of Truth」というアーキテクチャ

## 4. 記録の信頼性を担保する工夫（EXIF検証）

`app/record/page.tsx` および `lib/imageMetadata.ts` に実装された、**撮影時刻の裏付けチェック**は他の散歩・日記アプリではあまり見られない工夫。

- 画像のEXIFメタデータから撮影時刻を抽出し、「未来の時刻」「撮影から10分/24時間以上経過」などをフラグ化して記録に付与する
- ギャラリーからの選択と実際のカメラ撮影を区別し（`imageSource: 'camera' | 'gallery'`）、後から「その場で撮ったものかどうか」を判別できる材料を残す
- これにより、ミッション達成の実在性（本当にその場に行って撮ったか）を後から検証できる余地を残しており、将来的なランキング機能や不正防止機能の土台になり得る

## 5. 軽量な認証・パスワード設計

一般的なメール/SNS認証を避け、**7桁数字パスワード + 英数字ユーザーID**という独自のシンプルな認証方式を採用している（`lib/validation.ts`)。

- メールアドレス登録不要でオンボーディングの摩擦を最小化
- 予約語チェック（`admin`, `system` 等の前方一致禁止）でID空間の衝突・なりすましリスクを軽減
- パスワード忘れに備えた「バックアップ（JSONエクスポート）→ 復元」フローを用意し、アカウント復旧をサーバー側の個人情報なしで実現

## 6. 画像パイプラインの最適化

- クライアント側Canvas圧縮（1024×1024, 品質80%、超過時は自動で品質を段階的に下げて再圧縮）によりアップロード帯域とCloudinaryストレージコストを抑制（`lib/imageCompression.ts`)
- 撮影後は即座にCloudinaryへアップロードし、ローカルにBase64画像を保持しない設計でモバイル端末のメモリ消費を抑えている
- Cloudinary許可ドメイン + `sanposhin/{userId}` パスのみ表示許可するホワイトリスト方式で、外部URL混入によるなりすまし画像表示を防止

## 7. 管理者機能の作り込み

個人開発／小規模チーム運営のPWAとしては、管理画面の充実度が高い。

- ロールベースアクセス制御（superadmin / admin / moderator）
- 監査ログ（`audit-logs`コレクション）による管理者操作の追跡
- 日次・月次統計、メンテナンスモード、機能フラグ、広告設定など、運用者向けの「止める・切り替える」系のオペレーション機能が揃っている
- お問い合わせ管理（ステータス管理・担当者アサイン・内部メモ）でカスタマーサポート業務も内製化している

## 8. プライバシー・データ主権への配慮

- GDPR準拠を意識したアカウント完全削除機能（Firestoreログ全削除 + Cloudinary画像削除 + localStorage全消去の3段階）
- バックアップは自分のFirestoreデータをエクスポートしたJSONファイルであり、ユーザー自身がローカルにデータを保持できる（ベンダーロックインを避ける設計思想）

## まとめ

本アプリの独自性は、単一の派手な機能ではなく、
「**AIによる状況適応型の小さな目的付与** → **その場で撮った証拠としての写真** → **物語として蓄積されるアルバム**」
という一連の体験ループを、外部API障害時のフォールバックやオフライン同期まで含めて一貫して設計している点にある。個人開発PWAとしては、認証・画像パイプライン・管理機能まで含めた完成度が高い。
